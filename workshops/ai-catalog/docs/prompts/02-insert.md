# STEP 2 発話（指示文ではなく会話で言う）

`catalog/` の JSON を全部 PostgreSQL に入れて。スキーマは `docs/case-schema.md`。テーブル名は `cases`、`id` を主キーに。MCP の postgres だけで入れて（スクリプトは書かない）。何件かずつまとめて INSERT して、重複しても壊れないようにして。最後に件数を確認して。

---

見せること: テーブル作成の DDL → まとめ INSERT（数回） → 件数確認 を AI が MCP のツール呼び出しだけで組み立てる。
「正しい情報」はスキーマ文書とテーブル名。これを言わないと列名が毎回変わり、STEP 3 の指示文と食い違う。
「正しい指示」は MCP だけ／まとめて INSERT／重複耐性。言わないと、投入スクリプトを書き始める、1件ずつ48回呼ぶ、2回目の実行で主キー違反、のどれかが起きる。

時間の目安: 48件を SQL リテラルで流すと約50KB の出力。12件ずつなら4回。リハーサル1回目は修正なしで通った。
