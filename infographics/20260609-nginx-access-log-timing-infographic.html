Nginx Access Log Timing の見方

ECS / ALB の外形監視だけでは「Nginx・アプリ・クライアントのどこで遅いか」が切れない。Nginx access log に timing 変数を入れて、1リクエスト単位で切り分ける。
追加すべき最小セット request_time, upstream_connect_time, upstream_header_time, upstream_response_time, upstream_status, request_id

1. ログに足す項目

$request_time Nginxがクライアントから最初のバイトを読んでから、処理が終わるまでの全体時間。
$upstream_connect_time 上流アプリへの接続確立時間。TLS upstream なら handshake も含む。
$upstream_header_time 上流アプリに接続してから、レスポンスヘッダを受け取るまで。
$upstream_response_time 上流アプリに接続してから、レスポンス全体を受け取るまで。
$upstream_status 上流アプリが返したHTTPステータス。Nginxの $status と分けて見る。

2. 各 time が示す区間

request_time クライアント読み取り、Nginx処理、upstream待ち、クライアントへの送信までを含みうる。
connect_time 上流へのTCP/TLS接続。ここが高いならネットワーク、名前解決、接続枯渇を疑う。
header_time 上流が最初の応答を返すまで。アプリ処理・DB待ち・キュー滞留が出やすい。
response_time 上流レスポンスを最後まで受け取るまで。大きなレスポンスやstreamingで伸びる。

3. 推奨 log_format

log_format app_timing escape=json
'{"time":"$time_iso8601",'
'"request_id":"$request_id",'
'"remote_addr":"$remote_addr",'
'"xff":"$http_x_forwarded_for",'
'"method":"$request_method",'
'"host":"$host",'
'"uri":"$request_uri",'
'"status":$status,'
'"upstream_status":"$upstream_status",'
'"request_time":$request_time,'
'"upstream_connect_time":"$upstream_connect_time",'
'"upstream_header_time":"$upstream_header_time",'
'"upstream_response_time":"$upstream_response_time",'
'"upstream_addr":"$upstream_addr",'
'"request_length":$request_length,'
'"body_bytes_sent":$body_bytes_sent,'
'"user_agent":"$http_user_agent"}';

4. 遅い時の読み分け

uct高
接続が遅いupstream接続、TLS、ポート枯渇、名前解決、SG/NACL、アプリ受け口を確認。
uht高
アプリ初動が遅いDB、外部API、ロック、キュー、CPU飽和、GCを疑う。
urt高
レスポンス完了が遅い巨大レスポンス、streaming、upstream送信、Nginx bufferingを確認。
rtだけ高
クライアント側も疑うclient upload/download、ALB-Nginx間、Nginx処理、ログ上の差分を見る。
最短ルール: rt は全体、uct は接続、uht は初回応答、urt は上流完了。$status と $upstream_status は分けて見る。
