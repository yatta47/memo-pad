デプロイ

デプロイ = Task Definition の Revision を入れ替える

EC2 では AMI + Instance Refresh。ECS では Image を ECR に push → Task Definition Revision → Service 更新

Revision とは？
Task Definition を更新するたびに自動で採番される版番号（myapp:11 → myapp:12）。過去の Revision は消えず残るので、戻したい版を指定するだけでロールバックできる。Launch Template の Version と同じ感覚。
EC2 のデプロイ
① AMI を更新
▼
② Launch Template を更新
▼
③ Instance Refresh → 旧 EC2 を新 EC2 に
ECS のデプロイ
① Docker Image を build → ECR に push
▼
② Task Definition の新 Revision を作成
▼
③ Service を更新 → 旧 Task を新 Task に
ロールバックは「前の Revision を再適用するだけ」。入れ替え割合は minimum / maximum percent で制御。

Appendix

よくある確認 ── Q&A

運用で詰まったとき「どこを見るか」。EC2 時代の確認手順と対応している

Q. 今いくつ Task が動いている？
A. ECS Service の Running / Desired を見る。差があり Pending が残れば起動できていない。（≒ ASG の Desired / InService）
Q. なぜ Task が起動しない / すぐ落ちる？
A. Service Events と Task の停止理由 を見る。イメージ取得失敗・ヘルスチェック失敗・容量不足などが出る。
Q. アプリのログはどこ？
A. CloudWatch Logs / New Relic Logs（firelens 経由）。nginx・app・サイドカーそれぞれ確認できる。
Q. 通信が来ない / 502・503 が出る
A. ALB Target Group の Healthy / Unhealthy とヘルスチェックパスを確認。Unhealthy なら nginx/app の起動を疑う。
Q. どの版が動いている？
A. Service が参照している Task Definition の Revision を見る。（≒ Launch Template の Version）
Q. サイドカー（FireLens など）のバージョンを変えたいときは？
A. Task Definition の該当コンテナの image タグを上げて新 Revision を作り、Service を更新する。＝通常デプロイと同じで、app だけでなく Task ごとまるごと入れ替わる（サイドカー単体では差し替えない）。
迷ったら まず Service。Pending で止まっていないかを最初に見る。原因の多くは Service Events に出ている。
